<h2 align="center">Concordance</h2>

<p align="center"><strong>What your files already know about each other.</strong></p>

<p align="center">
  Your team writes markdown for the AI. Concordance turns it into a wiki for the humans:<br>
  point it at your git repositories and get a site where every word of your business has a page, with every place it is used.
</p>

| Repository | What it holds |
|---|---|
| [concordance](https://github.com/concordance-wiki/concordance) | The tool: the command line, the checks, the generated site, the linter and the plugins, published on npm as `@concordance-wiki/*`. |
| [demo-wiki](https://github.com/concordance-wiki/demo-wiki) | The wiki Concordance builds about itself: its configuration, its lock file and the [published site](https://concordance-wiki.github.io/demo-wiki/). |
| [demo-glossary](https://github.com/concordance-wiki/demo-glossary) | The vocabulary of the tool, one note per term, filed by domain. |
| [demo-specs](https://github.com/concordance-wiki/demo-specs) | Its specifications: screens, processes, rules, objects, APIs, roles and decisions. |
| [demo-briefs](https://github.com/concordance-wiki/demo-briefs) | Its working sessions: minutes, transcripts and decks. |

The three corpora are read by the tool as three sources of one wiki; every scenario of the configuration is exercised there, so the demo is also the test bed.
